## 5. Stage 5 — Window pop-out + mirrored-resize policy

- [x] 5.1 Server: smallest-client-wins resize (design D11, S1 Q1) — `PtySession` tracks each
      attached client's last size; the `resize` handler applies `min(cols)`×`min(rows)` across live
      attaches, recomputing on attach/detach/resize (replaces last-writer-wins). Tests: two attaches
      of different sizes → PTY at the min; detach relaxes up
- [x] 5.2 `?popout=1` client mode: capture the flag ONCE at boot (in-app pushState drops the
      query); hide strip/drawer/split/pop-out chrome; never read/write `palmux-split`; "⇱ return
      to main" per `docs/popout-protocol.md` (origin-validated postMessage; disabled with a hint
      when `window.opener` is null/closed); killed-tab → ended state, no auto-switch, no
      respawning reload
- [x] 5.3 "Open in new window" in the tab context menu, mobile sheet, and pane header (⧉) via
      `window.open('/<id>?popout=1', 'palmux-<id>', 'popup,width=1000,height=640')` — the window
      name dedupes repeat invocations. Popping out a split slot's tab KEEPS the main split (Q5 stay + mirror)
- [x] 5.4 Desktop tear-off: on strip-tab `dragend` outside the viewport with no internal drop
      target, `window.open` positioned near `screenX/Y` (clamped; coordinates are unreliable on
      some platforms — attempt-first); popup-blocked/degraded fallback = toast with an explicit
      open action (a first-class path, not an edge case)
- [x] 5.5 Verify multi-window behavior: two windows on one terminal mirror at the min size;

- [x] 5.6 Tests: popout mode chrome hiding + origin-validated return handling, menu/dragend pop-out
