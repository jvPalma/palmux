## Context

palmux shipped seven feature changes back-to-back with **no linter, no formatter, and no lint/format scripts anywhere** (confirmed: root and per-package `package.json` carry zero `eslint`/`prettier`/`oxlint`/`oxfmt`/`biome` deps or scripts). Stack facts that scope this audit:

- **Vite SPA, React 18** (`@types/react` ^18.3.18) — so every Next.js/RSC rule (`server-*`, `async-api-routes`, Suspense-streaming, `next/dynamic`) and every React-19-only rule (`use()` over `useContext`, dropping `forwardRef`, `<Activity>`, `useEffectEvent`) is **out of scope** and was excluded from the audit rather than reported as a false positive.
- The **client** is where the debt concentrates. `App.tsx` is a ~1175-line orchestration hub; there is **zero `React.memo` in the codebase**, and both `dragRatio` (per-frame, rAF-throttled) and `toast` (per copy-on-select) live at the App root, so the whole tree re-renders on those hot paths.
- The **server** is well-modularized (deep `SessionRegistry` + deep `PtySession` behind thin route adapters) — the architecture pass found little to change there.

This change installs the missing tooling and records a ranked, `file:line`-anchored findings catalog to work down. Findings were gathered by three parallel audits (Vercel React perf, Vercel composition, architecture deepening) against the real stack.

## Goals / Non-Goals

**Goals:**

- A reproducible `yarn lint` (Oxlint, incl. `perf` + `react-perf`) and `yarn format` (Oxfmt) gate, introduced fresh, matching the project's 2-space/single-quote/semicolon/trailing-comma style.
- Fix the high-impact React re-render/O(n²) hot-path findings (they hurt a per-keystroke/per-frame terminal app most).
- Decompose the `App.tsx` god-component along the seams the composition + architecture audits both identified, improving testability and AI-navigability.
- Every refactor behavior-preserving and gated by `yarn typecheck` + the 500+ existing tests staying green.

**Non-Goals:**

- No CI/workflow changes (project convention: CI only on explicit request).
- No React 19 upgrade (all React-19 advice is deferred, not applied).
- No behavior changes, no new product capabilities, no dependency additions beyond `oxlint` + `oxfmt`.
- Not a rewrite — the deep modules (`PtySession`, `SessionRegistry`, `SplitFocusContext`, protocol parsers, `MouseGate`, `WsClient` reconnection core) are explicitly left alone.

## Decisions

### D1 — Tooling: introduce, don't migrate

There is no ESLint/Prettier to migrate from, so `@oxlint/migrate` and `oxfmt --migrate` are unnecessary — configs are authored directly.

- **Oxlint** (`.oxlintrc.json`): enable `correctness` (default) + `perf` + `suspicious` categories and the `react`, `react-perf`, `import`, `unicorn` rule sets; pin `$schema`. Root `yarn lint` / `yarn lint:fix` run it across `packages/*`. Depend on `oxlint` only.
- **Oxfmt** (`.oxfmtrc.json`): `tabWidth: 2`, `semi: true`, `singleQuote: true`, `jsxSingleQuote: false`, `trailingComma: "all"`, `printWidth: 100`. Root `yarn format` (write) + `yarn format:check` (verify). The first repo-wide reflow lands as one isolated commit, separate from refactors.
- **`performance-lint-rules` is N/A**: that skill reviews the oxc _Rust_ linter's own rule implementations (`crates/oxc_linter/`), not a consumer TS project. Its applicable analog here is enabling Oxlint's `perf` category + `react-perf`, which D1 already does.

### D5 — Cross-lens convergence (do overlapping work once)

The App.tsx decomposition is one job seen through three lenses — sequence it so findings collapse together:

- **A1 (controller reducer) + A3 + A4 + A5** are facets of the same missing abstraction → one workspace-controller extraction.
- **C2 (`<SplitView>`) + C3 (`useTabGroups`) + C1/C5 (grouping provider)** decompose App's _rendering + group state_, complementary to A1's _navigation state_.
- **P2 + P5 + A2** all touch the group/order math → a shared `Map<id,groupId>` accessor and the lifted `normalizeOrder` land together.
- **P1 + P3 + P4 + P7** share the memo/root-state root cause → one re-render-hygiene pass.

## Risks / Trade-offs

- **Formatting churn**: the first `oxfmt --write` touches every file. Mitigation: land it as one isolated commit before any refactor, so behavioral diffs stay reviewable.
- **New-lint fallout**: introducing Oxlint on an unlinted codebase will surface a backlog. Mitigation: start with `correctness` + `perf` erroring and other categories as `warn`; fix or scope-down iteratively rather than blocking on a clean sweep.
- **Over-abstraction risk**: the A1 controller and C1/C2 compounds could be taken too far. Mitigation: the deletion test is the bar — extract only where complexity _concentrates_ (A1, A2 pass; A6/A7 are Speculative for a reason). Leave the already-deep modules untouched.
- **Behavior drift during refactor**: the only real hazard. Mitigation: the 500+ existing tests + `yarn typecheck` are the gate on every step; refactors that expose a new seam add a direct unit test (e.g. `reduce()` cases replacing full-render assertions).
- **Perf fixes that don't matter**: P6/P8/P9 are low-signal. Mitigation: they're explicitly ranked low; the top of D2 is where the wins are.
